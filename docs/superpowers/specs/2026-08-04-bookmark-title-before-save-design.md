# 收藏前自定义书签标题设计

## 目标

用户在扩展弹窗中收藏当前网页之前，可以直接查看并修改书签标题。确认收藏后，Edge 收藏夹和 Bookmark Recall 使用同一个最终标题，不需要收藏后再次编辑。

## 交互

- 扩展弹窗打开时读取当前活动标签页。
- 在文件夹选择器与收藏按钮之间显示“书签名称”输入框。
- 输入框默认填入当前标签页标题；标签页没有标题时使用当前 URL。
- 用户可以直接编辑标题，输入上限为 500 个字符。
- 标题按首尾去空格后的值保存。结果为空时禁用收藏按钮，不发起收藏或正文采集。
- 每次重新打开弹窗时重新读取当前标签页，不跨页面保留上次输入的标题。
- 现有文件夹选择、快速搜索和设置入口保持不变。

## 数据流

1. 弹窗初始化时并行读取扩展配置、Edge 文件夹树和当前活动标签页。
2. 当前标签页的标题或 URL 成为可编辑的初始标题。
3. 用户点击“收藏当前网页并保存正文”时，先验证当前页面为 HTTP(S) 页面，并规范化用户输入的标题。
4. 扩展读取当前页面的可读正文。
5. 扩展使用最终标题调用 `browser.bookmarks.create()`。
6. 扩展提交正文采集载荷时显式使用同一个最终标题，覆盖正文提取器返回的页面标题。
7. 后端保存该标题，因此 Edge 收藏名称与 Bookmark Recall 默认标题一致。

## 边界与错误处理

- 标题为空：收藏按钮禁用；即使通过其他方式触发保存，也应在创建 Edge 收藏前终止。
- 标题超过 500 个字符：输入框限制为 500，保存逻辑再次裁剪，匹配后端契约。
- 当前标签页没有标题：使用 URL 作为默认值。
- 当前页面不是 HTTP(S)：保留现有错误提示，不创建 Edge 收藏。
- 正文采集或后端提交失败：沿用现有错误提示；本次改动不改变当前失败补偿策略。
- 正文提取器返回不同标题：用户确认的标题优先，不得被覆盖。

## 代码边界

- 在扩展 `lib` 中增加纯函数，负责默认标题选择、标题规范化以及构造带最终标题的采集载荷。
- 弹窗组件只负责读取标签页、维护输入状态和调用纯函数。
- 不修改后端接口和数据库结构；现有 `title` 字段已满足需求。
- 不增加标题历史、AI 改名建议或自动命名规则。

## 测试与验收

- 单元测试先行，覆盖：
  - 标签页标题优先于 URL；
  - 缺少标题时回退到 URL；
  - 标题首尾空格被移除并限制为 500 个字符；
  - 空标题被拒绝；
  - 用户标题覆盖正文提取标题并进入后端载荷。
- 扩展类型检查与生产构建通过。
- 全量 `npm run verify` 通过。
- 手动验收：输入自定义标题收藏一个合成网页，确认 Edge 收藏名称和 Bookmark Recall 详情标题完全一致。
